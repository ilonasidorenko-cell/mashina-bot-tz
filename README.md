# Машина продаж · учебная сборка

Это скелет системы для модуля 2 Академии Solaris. Он намеренно маленький:
бот в Telegram, канал к моделям с резервной цепочкой и сторож. Всё на
стандартной библиотеке Python, без зависимостей, чтобы вы разбирались с
архитектурой и сервером, а не с чужим кодом.

Боевую систему Solaris этот комплект не содержит и не заменяет.

## Что внутри

| Файл | Зачем |
|---|---|
| `llm.py` | канал к моделям: основной через CLI Claude Code, резерв через роутер, Groq, DeepSeek; пишет `failover.log` |
| `bot.py` | Telegram-бот: отвечает через `llm.ask`, команда `/резерв` проверяет цепочку |
| `watchdog.py` | сторож: живой вызов модели, алерт вам в Telegram, если контур молчит |
| `systemd/` | юнит бота, юнит и таймер сторожа |
| `.env.example` | образец файла с ключами |

## Развёртывание

1. Возьмите VPS (Ubuntu 22.04 и новее), зайдите по SSH через Termius, поставьте `tmux`.
2. Распакуйте комплект:
   ```
   mkdir -p mashina_prodazh && tar xzf mashina_prodazh_uchebnaya.tar.gz -C mashina_prodazh
   cd mashina_prodazh && python3 -m venv venv
   ```
3. Поставьте официальный CLI Claude Code и настройте основной канал. Если у вас
   подписка Claude Max, это `claude login`: CLI напечатает ссылку и будет ждать код.
   На сервере браузера нет, поэтому ссылку открываете у себя на компьютере, при
   входе из России включаете VPN с сервером США, копируете код и вставляете в терминал.
   Если подписки нет, основным каналом ставите роутер или прямой ключ, это допустимо.
4. Заполните ключи:
   ```
   mkdir -p /etc/solaris && cp .env.example /etc/solaris/llm.env
   nano /etc/solaris/llm.env && chmod 600 /etc/solaris/llm.env
   ```
   Файл лежит вне каталога проекта специально: секреты не должны попасть в git.
5. Проверьте контур: `venv/bin/python llm.py` должен напечатать «РЕЗЕРВ ОК».
6. Поставьте сервисы:
   ```
   cp systemd/*.service systemd/*.timer /etc/systemd/system/
   systemctl daemon-reload
   systemctl enable --now mashina-bot mashina-watchdog.timer
   ```
7. Перезагрузите сервер (`reboot`) и убедитесь, что бот отвечает сам, без вас.

## Что проверяет домашка

1. Система живёт на VPS под systemd и переживает reboot.
2. Вход по SSH-ключу, парольный вход закрыт, секреты в отдельном файле с `chmod 600`.
3. Бот отвечает в Telegram.
4. Основной канал отвечает, резервная цепочка даёт «РЕЗЕРВ ОК».
5. Учения: вы сами гасите свой основной канал (стираете тот токен или ключ, на
   котором он работает), система продолжает отвечать с резерва. Доказательство —
   строка переключения из `failover.log` и ответ бота той же минуты.
6. Разбор полёта: что падало, как искали причину, чем починили. Это главный пункт.

## Частые грабли

- `unable to locate package mosh` — сначала `apt update`, потом `apt install mosh`.
- Бот молчит после перезагрузки — забыли `systemctl enable`, включён только `start`.
- «Секреты в .env внутри проекта» — проверьте `git check-ignore -v .env` и вынесите файл.
- CLI просит код при входе по подписке — смотрите шаг 3, вход делается один раз.
